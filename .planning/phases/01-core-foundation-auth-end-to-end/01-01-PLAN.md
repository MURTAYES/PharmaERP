# Plan 01-01: Server Scaffolding, MongoDB Connection, JWT Authentication & Field Stripping Serializer

## Goal
Scaffold the root monorepo and Node/Express backend (`/server`), establish a robust MongoDB Atlas connection, implement rate-limited JWT authentication (access + httpOnly refresh tokens) with bcrypt hashing, implement role guards (`owner` vs `pharmacist`), and build the server-side response serializer middleware that strips sensitive cost fields from Pharmacist responses.

## User Story
As a Pharmacy Staff member, I want to securely log in to the system with my credentials so that my session is authenticated and my permissions/views match my assigned role (Owner or Pharmacist) without exposing cost data to pharmacists.

## Tasks

### Task 1: Monorepo Root & Server Setup (Tracer)
- Initialize root `package.json` with concurrently/build scripts.
- Scaffold `/server` with `tsconfig.json`, `package.json`, and dependencies (`express`, `mongoose`, `jsonwebtoken`, `bcryptjs`, `cors`, `helmet`, `express-rate-limit`, `cookie-parser`, `zod`, `dotenv`, `vitest`, `supertest`, `tsx`).
- Configure MongoDB Atlas connection in `server/src/config/db.ts` with retry logic and Decimal128 schema options.
- Create Express app entry point `server/src/server.ts` with Helmet, CORS, CookieParser, and JSON body parser.

**Files Created/Modified:**

- `.env.example`

- `server/vitest.config.ts`
- `server/src/config/db.ts`
- `server/src/config/env.ts`

**Automated Verification:**
```bash
npm --prefix server run typecheck
```

### Task 2: User Model, Seeding & JWT Authentication Pipeline
- Create `User` Mongoose model in `server/src/models/User.ts` (username, passwordHash, fullName, role: `owner` | `pharmacist`, isActive, lastLogin).
- Implement password hashing with bcryptjs (10 salt rounds).
- Create database seed utility in `server/src/scripts/seed.ts` that automatically creates the default Owner account (`admin` / `admin123`) if no owner exists.
- Implement `authMiddleware` in `server/src/middleware/auth.ts` to verify access tokens.
- Implement `roleGuard` in `server/src/middleware/roleGuard.ts` to restrict endpoints by role.
- Implement `authController.ts` with login, refresh token, logout, and get current user (`/api/auth/me`) routes with Zod request validation and rate limiting.

**Files Created/Modified:**
- `server/src/models/User.ts`
- `server/src/middleware/auth.ts`
- `server/src/middleware/roleGuard.ts`
- `server/src/middleware/validate.ts`
- `server/src/controllers/authController.ts`
- `server/src/routes/authRoutes.ts`
- `server/src/scripts/seed.ts`

**Automated Verification:**
```bash
npm --prefix server test src/tests/auth.test.ts
```

### Task 3: Server-Side Response Serializer Middleware & Tests
- Implement `responseSerializer` middleware in `server/src/middleware/serializer.ts` that intercepts outgoing `res.json` calls.
- Recursively sanitize response objects to remove sensitive keys (`purchasePrice`, `purchasePricePerPiece`, `cost`, `profit`, `stockValuation`, `margin`) whenever `req.user.role === 'pharmacist'`.
- Preserve exact Decimal128 string serializations and non-sensitive fields.
- Write unit and integration tests verifying that Owner receives full cost fields while Pharmacist receives sanitized payloads with zero cost leakage.

**Files Created/Modified:**
- `server/src/middleware/serializer.ts`
- `server/src/tests/auth.test.ts`
- `server/src/tests/serializer.test.ts`

**Automated Verification:**
```bash

```
