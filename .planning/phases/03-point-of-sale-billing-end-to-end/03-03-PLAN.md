# Plan 03-03: Server-Side Held Bills API and Multi-Terminal Cart Synchronization

## Goal
Implement the backend routes and controllers to allow pharmacists to hold carts to the server, query held bills across terminals, retrieve held cart contents, and release/resume them seamlessly.

## Proposed Changes

### 1. Held Bills Controller & Endpoints (`server/src/controllers/heldBillController.ts`)
- `POST /api/pos/held-bills`:
  - Validates cart payload (lines, quantities, units, discount, customer name/phone, custom note).
  - Generates a human-friendly `billReference` (e.g., `HOLD-101` or customer name).
  - Saves document to `HeldBill` collection.
- `GET /api/pos/held-bills`:
  - Returns list of open held bills sorted by creation time (newest first).
- `GET /api/pos/held-bills/:id`:
  - Returns the full cart payload for resuming.
- `DELETE /api/pos/held-bills/:id`:
  - Removes the held bill upon checkout completion or manual discard.

### 2. Routes & Express Integration (`server/src/routes/posRoutes.ts`)
- Mount held bill routes under `/api/pos/held-bills`.
- Protect with `requireAuth` middleware.

### 3. Automated Tests
- Create `server/src/tests/heldBills.test.ts`:
  - Test saving a held bill with multiple line items.
  - Test listing active held bills.
  - Test fetching a held bill by ID.
  - Test deleting a held bill.

## Verification
- `npm --prefix server test` passes all tests cleanly.
