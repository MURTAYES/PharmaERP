# Plan 02-02: Batch Stock Receiving Engine, Duplicate Merging & Cost-Missing Workflow

**Phase:** Phase 2: Inventory & Stock Management (End-to-End)
**Type:** Backend Stock Ingestion & Batch Engine
**Requirements Covered:** INVT-05, INVT-06, INVT-07, INVT-08

## Goal
Implement the `Batch` model, batch receiving workflow supporting multi-unit inputs (pieces/strips/boxes), duplicate batch merging (matching itemId + batchNumber + expiryDate), cost-missing flag for pharmacist receiving, tri-bucket stock tracking (`qtySellable`, `qtyDamaged`, `qtyExpired`), and atomic creation of initial `RECEIVE` stock movement ledger entries.

## User Stories
- As a Pharmacist, I can rapidly receive incoming medicine stock in boxes, strips, or pieces without needing to enter a purchase price, with the system automatically converting units and flagging cost as missing.
- As an Owner, I can enter purchase prices per piece/strip/box upon receiving, or update cost later on batches previously received by pharmacists.
- When stock is received for an already existing batch (same item, batch number, and expiry date), the system automatically adds the new quantity to the existing batch's sellable stock rather than creating duplicate batch records.

## Implementation Details

### 1. Batch Model (`server/src/models/Batch.ts`)
- Fields:
  - `itemId` (ObjectId -> Item, required, indexed)
  - `batchNumber` (string, required, uppercase trimmed)
  - `expiryDate` (Date, required, indexed)
  - `qtySellable` (number, min: 0, default: 0)
  - `qtyDamaged` (number, min: 0, default: 0)
  - `qtyExpired` (number, min: 0, default: 0)
  - `purchasePricePerPiece`: `Types.Decimal128` (optional, Owner only)
  - `isCostMissing`: boolean (default: false)
  - `supplierName`: string (optional)
  - `createdAt`: Date
  - `updatedAt`: Date
- Compound unique index: `{ itemId: 1, batchNumber: 1, expiryDate: 1 }`

### 2. Stock Receiving Service & Controller (`server/src/controllers/batchController.ts`)
- Endpoints:
  - `POST /api/batches/receive`:
    - Input: `itemId`, `batchNumber`, `expiryDate` (ISO or `DD/MM/YYYY` or `MM/YYYY`), `unit` (`piece` | `strip` | `box`), `quantity` (number), `purchasePrice` (optional, can be per-piece, per-strip, or per-box), `supplierName`.
    - Unit Math:
      - If unit is `'piece'`: `totalPieces = quantity`
      - If unit is `'strip'`: `totalPieces = quantity * item.unitHierarchy.piecesPerStrip`
      - If unit is `'box'`: `totalPieces = quantity * item.unitHierarchy.piecesPerStrip * item.unitHierarchy.stripsPerBox`
    - Cost Math:
      - If `purchasePrice` provided (Owner): compute `purchasePricePerPiece` based on unit, set `isCostMissing = false`.
      - If `purchasePrice` omitted: `isCostMissing = true`.
    - Deduplication / Merge:
      - Query existing batch with `{ itemId, batchNumber: batchNumber.toUpperCase(), expiryDate }`.
      - If found: increment `qtySellable += totalPieces`. If `purchasePricePerPiece` was provided and previous batch was cost-missing, update cost and clear `isCostMissing`.
      - If not found: create new `Batch` record with `qtySellable = totalPieces`.
    - Ledger Event:
      - Append `StockMovement` with `type: 'RECEIVE'`, `qtyChangePieces: totalPieces`, `bucketTo: 'sellable'`.
  - `GET /api/batches/by-item/:itemId`: List all batches for an item (sorted by `expiryDate` ASC - FEFO).
  - `PUT /api/batches/:id/cost`: Owner-only endpoint to update purchase price and clear `isCostMissing`.

### 3. Automated Tests (`server/src/tests/batchReceiving.test.ts`)
