# Requirements Archive: PharmaERP v1.0 MVP

**Archived:** 2026-10-03
**Milestone:** v1.0 MVP
**Status:** Shipped (100% Verified)
**Core Value:** Accurate batch-wise stock with expiry visibility and fast counter billing — every sale traces back to a specific batch, every price override is recorded, and stock can never go negative through concurrent operations.

---

## Shipped Requirements (v1.0)

### Authentication & Access Control
- [x] **AUTH-01**: User can authenticate with username and password using JWT with bcrypt hashing *(Validated in Phase 1)*
- [x] **AUTH-02**: Role-based access control enforces Owner (full administrative access) vs Pharmacist (counter operations only) *(Validated in Phase 1)*
- [x] **AUTH-03**: Rate limiting protects authentication and sensitive API endpoints *(Validated in Phase 1)*
- [x] **AUTH-04**: User session persists across browser refresh with secure token refresh and logout *(Validated in Phase 1)*
- [x] **AUTH-05**: Server-side field serializer strips purchase price, cost, profit, and valuation fields from pharmacist API responses *(Validated in Phase 1)*

### Inventory & Stock Management
- [x] **INVT-01**: User can manage item master (trade name, generic name, category, manufacturer, shelf location, low-stock threshold) *(Validated in Phase 2)*
- [x] **INVT-02**: User can configure unit conversion hierarchy per item (base piece, strips, boxes with pieces-per-unit) *(Validated in Phase 2)*
- [x] **INVT-03**: User can set MRP per piece with derived strip and box prices *(Validated in Phase 2)*
- [x] **INVT-04**: User can search items with type-ahead search (<300ms) by trade name, generic name, or item code *(Validated in Phase 2)*
- [x] **INVT-05**: User can receive stock per batch (batch number, expiry date, quantity in pieces/strips/boxes, purchase price, MRP, supplier name) *(Validated in Phase 2)*
- [x] **INVT-06**: System deduplicates received batches by adding incoming quantity to existing batch matching item, batch number, and expiry *(Validated in Phase 2)*
- [x] **INVT-07**: Pharmacist can receive stock without entering purchase price (batch automatically flagged as cost-missing) *(Validated in Phase 2)*
- [x] **INVT-08**: System tracks three separate stock buckets per batch (sellable, damaged, expired) *(Validated in Phase 2)*
- [x] **INVT-09**: Owner can adjust stock between buckets or write off stock with mandatory reason entry *(Validated in Phase 2)*
- [x] **INVT-10**: System provides expiry tracking and dashboard alerts across configurable windows (90, 60, 30 days) and expired status *(Validated in Phase 2)*
- [x] **INVT-11**: System generates low-stock alerts when total sellable pieces drop below item threshold *(Validated in Phase 2)*
- [x] **INVT-12**: System maintains an append-only stock movement ledger recording all inventory transitions *(Validated in Phase 2)*

### Billing & Point of Sale
- [x] **POS-01**: Pharmacist can use a fast, keyboard/touch-optimized billing interface with autofocus and shortcut keys *(Validated in Phase 3)*
- [x] **POS-02**: System automatically suggests the earliest-expiring batch (FEFO order) when an item is selected *(Validated in Phase 3)*
- [x] **POS-03**: Pharmacist can select a non-FEFO batch without being blocked, automatically flagging the invoice line item *(Validated in Phase 3)*
- [x] **POS-04**: Pharmacist can select sale unit (piece, strip, box) with automatic price and piece-quantity calculation *(Validated in Phase 3)*
- [x] **POS-05**: Pharmacist can override unit price on any line item (never blocked, recorded on invoice and logged) *(Validated in Phase 3)*
- [x] **POS-06**: Pharmacist can manage cart line items (add, edit quantity/unit, remove, instant line subtotal) *(Validated in Phase 3)*
- [x] **POS-07**: Pharmacist can hold current bill to server and resume any held bill later from any terminal *(Validated in Phase 3)*
- [x] **POS-08**: Pharmacist can apply an invoice-level percentage discount *(Validated in Phase 3)*
- [x] **POS-09**: System computes global charges (percentage charges applied after discount, fixed charges applied once per invoice) *(Validated in Phase 3)*
- [x] **POS-10**: Pharmacist can process payment via Cash (with change due calculation), Card, Mobile Payment (bKash/Nagad), or Split Payment *(Validated in Phase 3)*
- [x] **POS-11**: System executes atomic checkout transaction (counter increment, invoice creation, stock deduction with $gte guard, ledger entry) *(Validated in Phase 3)*
- [x] **POS-12**: System generates sequential gap-free invoice numbers (INV-000001) via atomic database counters *(Validated in Phase 3)*
- [x] **POS-13**: System creates an immutable invoice snapshot storing item names, batch numbers, expiry dates, units, prices, and override flags *(Validated in Phase 3)*
- [x] **POS-14**: Pharmacist can print thermal receipts (58mm/80mm) formatted via browser print stylesheet (@page CSS) *(Validated in Phase 3)*
- [x] **POS-15**: All monetary calculations use Decimal128 precision with unrounded intermediate math and 2dp round-half-up grand totals *(Validated in Phase 3)*

### Returns & Credit Notes
- [x] **RET-01**: User can initiate sales return against an existing invoice number with item and batch verification *(Validated in Phase 4)*
- [x] **RET-02**: User can select return quantities and assign returned stock to a specific destination bucket (sellable, damaged, expired) *(Validated in Phase 4)*
- [x] **RET-03**: System calculates proportional refund amounts accounting for original invoice discounts and percentage charges *(Validated in Phase 4)*
- [x] **RET-04**: System atomically executes return (stock bucket increment, return record creation, credit note generation, ledger entry) *(Validated in Phase 4)*
- [x] **RET-05**: System issues sequential credit notes (CN-000001) *(Validated in Phase 4)*
- [x] **RET-06**: Owner can generate supplier return invoices (SRT-000001) for expired/damaged stock, deducting from designated buckets *(Validated in Phase 4)*

### Analytics & Reporting
- [x] **RPT-01**: Owner can view real-time dashboard with sales metrics, invoice count, payment breakdown, alert counts, and top-selling items *(Validated in Phase 5)*
- [x] **RPT-02**: Owner can view sales summary report filterable by date range, payment method, or user *(Validated in Phase 5)*
- [x] **RPT-03**: Owner can view sales by item report showing units sold and revenue *(Validated in Phase 5)*
- [x] **RPT-04**: Owner can view profit and loss report (revenue minus cost snapshot, excluding cost-missing lines until filled) *(Validated in Phase 5)*
- [x] **RPT-05**: Owner can view price override report displaying all modified prices with user attribution and variance *(Validated in Phase 5)*
- [x] **RPT-06**: Owner can view non-FEFO sales report highlighting sales where older stock was bypassed *(Validated in Phase 5)*
- [x] **RPT-07**: Owner can view stock valuation report at cost price and retail price *(Validated in Phase 5)*
- [x] **RPT-08**: Owner can view expiry report grouped by warning windows and expired batches *(Validated in Phase 5)*
- [x] **RPT-09**: Owner can view low stock report listing items below reorder thresholds *(Validated in Phase 5)*
- [x] **RPT-10**: Owner can view returns report summarizing returned items, refund amounts, and destination buckets *(Validated in Phase 5)*
- [x] **RPT-11**: Owner can view stock movement ledger report filterable by item, batch, movement type, and date range *(Validated in Phase 5)*
- [x] **RPT-12**: User can export any tabular report to CSV format *(Validated in Phase 5)*

### Settings & System Administration
- [x] **SYS-01**: Owner can configure pharmacy profile (name, address, phone, receipt header/footer, currency symbol) *(Validated in Phase 1)*
- [x] **SYS-02**: Owner can configure receipt printing settings (58mm vs 80mm default width, header display) *(Validated in Phase 1)*
- [x] **SYS-03**: Owner can configure global invoice charges (tax/VAT percentages, fixed fees, active toggles) *(Validated in Phase 1)*
- [x] **SYS-04**: Owner can configure expiry alert threshold windows (default 90, 60, 30 days) and low stock defaults *(Validated in Phase 1)*
- [x] **SYS-05**: Owner can manage medicine categories *(Validated in Phase 1)*
- [x] **SYS-06**: Owner can manage user accounts (create, assign role, reset password, activate/deactivate) *(Validated in Phase 1)*
- [x] **SYS-07**: System maintains an append-only immutable audit log for authentication, price overrides, stock adjustments, settings changes, and supplier returns *(Validated in Phase 1)*
