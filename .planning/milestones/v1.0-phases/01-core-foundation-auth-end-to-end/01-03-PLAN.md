# Plan 01-03: React/Vite Client Scaffolding, Clinical Design System, Top Navigation Shell & Management UI

## Goal
Scaffold the `/client` React/Vite application, configure Tailwind CSS with the exact clinical design tokens (`Plus Jakarta Sans`, `JetBrains Mono`, Material Symbols Outlined, `#00685f` deep teal palette), build the Top Navigation application shell, implement `AuthContext` with automatic token refresh interceptors, and deliver complete, interactive UI views for Login, Dashboard overview, User Management, Pharmacy Settings, and the Audit Log viewer.

## User Story
As a Pharmacy Staff member (Owner or Pharmacist), I want a fast, beautiful, clinical-grade web application interface with responsive top-bar navigation so that I can log in, view live pharmacy status, manage settings, and administer users efficiently on desktop and tablet devices.

## Tasks

### Task 1: Client Project Scaffolding & Clinical Design Tokens
- Scaffold `/client` using Vite with React and TypeScript.
- Install dependencies: `react-router-dom`, `@tanstack/react-query`, `tailwindcss`, `clsx`, `tailwind-merge`, `sonner`, `lucide-react`, `axios`.
- Configure `tailwind.config.js` with the exact clinical color tokens from the design prototype:
  - `primary`: `#00685f`, `primary-container`: `#008378`, `on-primary`: `#ffffff`
  - `secondary`: `#006b5f`, `secondary-container`: `#6df5e1`, `secondary-fixed`: `#71f8e4`
  - `surface`: `#faf8ff`, `surface-container-low`: `#f2f3ff`, `surface-container-lowest`: `#ffffff`
  - `on-surface`: `#131b2e`, `on-surface-variant`: `#3d4947`
  - `error`: `#ba1a1a`, `error-container`: `#ffdad6`
- Configure `client/index.html` with Google Fonts `Plus Jakarta Sans` and `JetBrains Mono`, plus Material Symbols Outlined icons.
- Implement reusable UI primitives (`Button`, `Card`, `Badge`, `Modal`, `Input`, `Select`, `Table`) in `client/src/components/common/`.

### Task 2: Axios API Client, AuthContext & Login View
- Create Axios instance in `client/src/services/api.ts` with base URL `/api`, credentials (`withCredentials: true`), and interceptors that automatically catch 401s and call `/api/auth/refresh` to restore the access token seamlessly.
- Implement `AuthContext` in `client/src/context/AuthContext.tsx` providing `user`, `role`, `login()`, `logout()`, and `isAuthenticated`.
- Implement `ProtectedRoute` component in `client/src/components/layout/ProtectedRoute.tsx` handling auth checks and role permissions (`requiredRole`).
- Create `Login.tsx` view with clinical styling, responsive layout, username/password fields, loading states, and toast error notifications.

### Task 4: User Management, Pharmacy Settings & Audit Log Views
- Implement `Users.tsx` view (Owner only):
  - User list table with role chips (`Owner` / `Pharmacist`), active status badges, last login timestamps.
  - "Create User" modal with role selector and password validation.
  - Password reset modal and toggle user active status action.
- Implement `Settings.tsx` view (Owner only):
  - Pharmacy profile form (name, address, phone, email, currency, receipt header/footer).
  - Receipt width selector (80mm standard vs 58mm compact).
  - Global charges manager (add percentage/fixed charges, toggle active).
  - Expiry alert threshold inputs (90 / 60 / 30 days).
  - Category manager (add/remove medicine categories).
- Implement `AuditLogs.tsx` view (Owner only):
  - Paginated audit log table displaying timestamps, username, action types (`LOGIN`, `SETTINGS_UPDATE`, etc.), IP address, and payload diff inspection modal.
