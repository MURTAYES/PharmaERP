# Plan 03-02: Atomic POS Checkout Transaction Service, FEFO Batch API, and Stock Guard

## Goal
Implement the core backend POS operations: an API to discover sellable FEFO batches for any medicine, and an atomic checkout endpoint that verifies pricing, applies conditional `$gte` stock deductions, creates sequential invoices, and writes ledger entries inside a MongoDB transaction.

## Proposed Changes

### 1. FEFO Batches Discovery API
- Implement `GET /api/pos/items/:itemId/batches`:
  - Queries active batches with `qtySellable > 0` sorted by `expiryDate ASC`.
  - Marks the first active batch as `isFefo: true`.
  - Serializer strips cost data for pharmacist role.

### 2. Atomic Checkout Service & Endpoint
- Implement `POST /api/pos/checkout`:
  - Zod validation schema for checkout payload (lines, discountPercent, payment method/tender, customer info).
  - Validates and recalculates all line totals and invoice amounts using `pricingEngine`.
  - Opens MongoDB session and starts multi-document transaction:
    1. Iterates over line items and performs conditional atomic stock deduction:
       ```typescript
       await Batch.findOneAndUpdate(
         { _id: line.batchId, qtySellable: { $gte: line.quantityPieces } },
         { $inc: { qtySellable: -line.quantityPieces } },
         { session, new: true }
       );
       ```
       If any batch has insufficient stock, aborts transaction immediately with descriptive error.
    2. Generates next sequential invoice number (`INV-000001`) with session.
    3. Identifies non-FEFO lines by checking if earlier expiring batches had available stock at checkout time.
    4. Records immutable `Invoice` snapshot with line item snapshots, price override flags, and non-FEFO indicators.
    5. Records `StockMovement` entries with `type: 'SALE_DEDUCT'`.
    6. If price overrides exist, writes an audit record to `AuditLog`.
    7. Commits transaction and returns created invoice.

### 3. Invoice Query Routes
- Implement `GET /api/pos/invoices` (paginated invoice list with date and search filters).
- Implement `GET /api/pos/invoices/:id` or `/by-number/:invoiceNumber` (detailed invoice snapshot).

### 4. Automated Tests
- Create `server/src/tests/posCheckout.test.ts`:
  - Test successful checkout with single and multiple lines.
  - Test transaction rollback when stock is insufficient (`$gte` guard).
  - Test non-FEFO flag detection and price override recording.
  - Test role-based field stripping on invoice endpoints.
